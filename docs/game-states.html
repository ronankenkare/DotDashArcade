02 · Behavioral view

A run has one active state.

The interface moves from selection to readiness to active play. Hits loop the run forward; a miss stops it; interruptions safely return the player to instructions.

Game-state machine

The main path begins with choosing a mode. Hover a named state—or use the preview buttons—to see the corresponding simulator capture.

One miss ends the run 
stateDiagram-v2
    [*] --> Home: App launches
    Home --> Ready: Select mode + Play
    Ready --> Running: Start / reset()

    Running --> Running: CADisplayLink frame / advance marker
    Running --> TapDecision: Player taps / handleTap()

    state TapDecision <>
    TapDecision --> PerfectHit: inPerfect(markerPos)
    TapDecision --> GoodHit: inZone(markerPos)
    TapDecision --> GameOver: outside target

    PerfectHit --> Progression: score +1 / strong feedback
    GoodHit --> Progression: score +1 / normal feedback
    Progression --> Running: speed up + resize + relocate + theme

    GameOver --> Running: Play Again / reset()
    GameOver --> Ready: Change mode
    Ready --> Home: Navigate back

    Running --> Ready: App inactive or backgrounded
    Running --> Ready: Change mode

    note right of Running
      running = true
      marker and particles update each frame
    end note

    note right of GameOver
      running = false
      save mode-specific best
      show results overlay
    end note

Important lifecycle behavior: returning from the background restarts the display link, but it does not silently resume the previous run. The player explicitly starts again from the help overlay.
