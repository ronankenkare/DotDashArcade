03 · Runtime view

One tap fans out into feedback.

Input arrives through the game bar, GameState classifies the marker position, then updates rules and feedback before SwiftUI renders the published result.

Tap-to-outcome sequence

Read downward. The center choice shows the only major runtime branch: hit or miss.

Synchronous decision path 
sequenceDiagram
    autonumber
    actor Player
    participant Bar as GameBarView
    participant State as GameState
    participant Device as Haptics
    participant Store as UserDefaults
    participant UI as SwiftUI + Canvas

    Player->>Bar: Tap screen
    Bar->>State: handleTap(screenWidth)

    alt Game is not running
        State->>State: reset()
        State->>State: Load current mode settings
        State-->>UI: Publish fresh run state
    else Game is running
        State->>State: inZone(markerPos)

        alt Marker is inside target
            State->>State: inPerfect(markerPos)
            State->>State: score += 1
            State->>Device: Success or warning haptic
            Device-->>State: Feedback emitted
            State->>State: Spawn good particle burst
            State->>State: Multiply speed by hit quality
            State->>State: Clamp target width to mode minimum
            State->>State: Pick a new target center
            State->>State: Select theme for new score
        else Marker is outside target
            State->>State: Spawn failure particle burst
            State->>State: running = false / gameOver = true
            State->>Store: Save max(best, score) for mode
            Store-->>State: Best score persisted
            State->>State: showHelp = true
        end

        State-->>UI: @Published properties changed
    end

    UI-->>Player: Redraw bar, score, particles, and overlay

The frame loop runs alongside taps

CADisplayLink repeatedly advances the marker and particle state. Taps do not create a separate loop; they modify the same GameState that the next frame renders.

sequenceDiagram
    participant Display as Display Link
    participant State as Game State
    participant Physics as Marker and particles
    participant Canvas as SwiftUI Canvas

    loop Every display refresh
        Display->>State: Send frame timestamp
        State->>State: Compute elapsed time
        State->>State: Clamp elapsed time to 50 ms
        alt Run is active
            State->>Physics: Advance marker for elapsed time
            Physics-->>State: Return bounded position and direction
        end
        State->>Physics: Update particles for elapsed time
        Physics-->>State: Return live particles
        State-->>Canvas: Publish render state
        Canvas->>Canvas: Draw bar, target, marker, particles
    end
